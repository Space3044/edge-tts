# Agent Note: 区分视频缺少 AI 字幕与账号拒绝

Status: implemented

## Problem

批量学习材料请求 `source=audio` 时，网关连续返回 `caption_failed`，`tried` 只显示账号 `rejected`，并附次日 UTC 零点。真实上游 HTTP 200 内是 `code: 409, message: "AI caption not found"`。调度器丢弃具体原因，同一视频最多换三个账号并增加失败计数、设置冷却，容易被误解为整个账号池失效或当天额度耗尽。

## Decision

上游 `code=409` 且消息明确为 `AI caption not found` 时，客户端返回 `caption_not_found`。调度器把它视作本视频本次无可用 AI 字幕，保留上游消息并停止换账号，不修改账号用量、额度、登录状态或冷却。HTTP 网关以 409 和同名错误码返回，现有 `tried` 数组格式保持兼容；其他 409 继续走原来的失败处理。

只有确认可用账号池全部因 daily-limit 停泊时才给非空 `resetAt`。局部失败、没有可用账号、登录问题和普通冷却不承诺次日恢复。没有自动回退原生字幕，也没有新增未经核实的生成接口或轮询。

## Alternatives considered

- **继续遍历账号池**：可能在账号相关错误时成功，但当前响应明确描述视频字幕缺失，六个账号已返回相同类别；继续轮换会无谓冷却健康账号，因此单次失败停止。
- **把 409 都视为缺字幕**：实现最短，但会误吞其他冲突或权限问题，因此同时匹配明确的上游消息。
- **自动改用 json3**：可让调用方继续分析文本，但不是用户请求的真实词级时间轴；来源降级由调用方单独决定。

## Consequences

调用方能够区分视频缺字幕和账号故障，避免误导性的额度恢复时间与失败计数。现有调用方如只按 HTTP 502 处理普通失败，需要兼容新 409 错误码。修复不意味着新视频已经可以生成 AI 字幕；目前网关只有 GET 读取调用，实际生成前置条件仍待验证。

## Verification

- 使用已配置账号对随机样本直接请求上游，返回 HTTP 200、body code 409、`AI caption not found`，没有额度响应头。
- 使用网关历史文档样本 `npka43vhwNo` 请求同一接口，返回 108 段，全部带 `words`，共 1,056 个词；响应头 `x-quota-limit=2`、`x-quota-remaining=1`。这仅证明该视频和账号当时可读取，不推广为任意新视频可生成或所有账号额度相同。
- SQLite 回归检查 HTTP 200/409 内的缺字幕、其他 409、单次请求停止、账号行完全不变、HTTP 错误透传，以及局部失败不返回虚假重置时间。Trancy gateway、quota、代码卫生与 README 检查通过。
- 本地修复未发布，未修改远端账号、额度或已有字幕。诊断所用上游读取可能按服务规则扣额；批量调用方已记录请求次数。
